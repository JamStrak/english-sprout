| 标记 | 表示什么 |
| --- | --- |
| 人工验收通过 | 用户已试听并认可这个版本，不由自动检查代填 |

## 以后新增配音的正确顺序

1. 在正式 APP 工程核对课程 ID、音色路由、已定稿文案和重复表达，沿用生产交接手册规定的音色及模型。
2. 用自研工作台制作或组织项目任务。确需批次脚本时，仍使用经核对的制作环境，保留逐条规格、模型/工具版本、参数、原始音频、处理步骤与质检回执。
3. **生成完成就登记验收库**，不能只交最终 MP3。当前系统通过项目 ZIP 导入，不会自动监听所有外部脚本的输出；新增批次适配器需遵守工作台 `distribution/docs/ASSET_REVIEW.md` 的 schemaVersion 1 契约。待选素材的 `deployedVersion` 留空。
4. 用户在工作台试听、批注和选首选；技术检查通过不能代替人工听感通过。按本次用户授权范围接入 APP，不把点「首选」当作发布指令。
5. 接入后从实际代码与声音包重新导出快照，更新真实 APP 引用；导出完整备份给下一 AI，交回句单、批次规格、回执、Git 提交和未完成项。完整快照只能从实际已接入工程导出，不能用候选清单冒充。

当前适配器用于已有 APP 快照；新类型或新回执结构必须补充映射与验证，不能把没识别到的文件静默称作已登记。

## 从 APP 导出新的实际快照

在正式工程执行，输出必须是新目录：

```powershell
node scripts/export-xiaoya-voice-review.mjs --out "test-results/voice-review-export-新批次"
node --test tests/xiaoya-voice-review.test.mjs
```

导出器读取现有构建声音清单及源码映射，校验音频、图片与已有回执的哈希；没有写入 APP 资源、重新生成或自动通过审核的行为。声音包过期时先按生产手册构建，再导出。

将目录内文件打成 ZIP，`manifest.json` 应直接位于 ZIP 根部，不能套一层目录。下面示例在正式工程运行，目标文件不得已存在：

```python
from pathlib import Path
from zipfile import ZipFile, ZIP_DEFLATED
source = Path("test-results/voice-review-export-新批次")
with ZipFile("test-results/voice-review-新批次.zip", "x", ZIP_DEFLATED) as bundle:
    for path in source.rglob("*"):
        if path.is_file():
            bundle.write(path, path.relative_to(source).as_posix())
```
