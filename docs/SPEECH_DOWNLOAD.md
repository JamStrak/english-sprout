# 小耳朵下载与恢复（v1.7.3）

用户在电脑浏览器看到10%长时间不动，随后反馈到37%；说明该次下载仍在继续，不能据此认定其设备发生永久死锁。未读取或清理用户实际浏览器缓存。本次处理已独立复现的无反馈与悬挂路径。

## 已确认问题

- 旧进度等256KB整段下载且cache.put完成后才刷新；慢传输及缓存写入停顿均表现为百分比静止。
- 网络每次90秒，最多四次，却没有重试阶段提示；fetch/body忽略abort时原超时也无法保证返回。缓存open/match/put/delete和缓存body/json没有时限。
- 真实GitHub脚本压缩协商会改变Range表示：identity总长5804485，而gzip表示总长2393051；压缩Range返回206+gzip或416，不能用解码后的JavaScript字节偏移续传。模型0和4MB两段实际206、256KB、total41184862、无Content-Encoding，SHA与本地相同，未在服务器10%处复现固定故障。

## 当前行为

src/speech-download.js保留speech-v1缓存、原模型URL、256KB分段和最多三并发，复用既有完整文件/已校验完整分段。ReadableStream每批字节更新进度，15秒没有新字节自动重试；每批到达重新计时，慢但仍在传输不会因总耗时被误判。显式截止独立于AbortSignal，迟到的body结果不能接纳为完整分段。

缓存每项最多等5秒；不可用时仅禁用本次缓存访问，继续用内存完成，不清学习数据、不清其他缓存、不假称已离线保存。进度先报告后等待保存；保存完整文件成功才清理其已用分段。网络及缓存取消仍立即退出。

脚本用完整GET，允许浏览器正常压缩；完整模式拒绝206短响应，不硬编码脚本大小（本机与Linux换行字节不同）。模型继续Range续传，每次准备只探测一次Range能力；恢复时服务器忽略Range也只接收一次完整文件。显式no-store识别资源网络请求绕过SW二次缓存路径，普通离线读取仍保留。

src/speech-local.js发出下载百分比/已到字节、连接慢自动续传、保存、打开模型与准备完成等阶段。一次分段重试耗尽后按3/6/12/24/30秒恢复，联网事件可提前唤醒。后加入观察者立即收到当前状态；前台评分15秒等待结束后仍能看到后台准备进度，儿童可先开口练。首次准备后台总上限仍30分钟，脚本执行上限60秒、模型打开上限120秒；下载优化不能保证所有公网线路的传输速度。

## 验证

- tests/speech-download.test.js：原分段校验、断点、离线、Range不支持、配额失败、取消与并发限制。
- tests/speech-download-recovery.test.js：缓存/网络body挂起、独立时限、持续流不误超时、实时进度、取消、压缩完整GET、短响应拒绝与SW穿透。
- tests/speech-download-browser.cjs：真实模型从约10%缓存断点开始，真实HTTP停顿与503，自动恢复、后加入状态、已缓存前缀不重取、真实Vosk及冷页离线。
- tests/main-real-speech.cjs：真实录音与模型进入正常学习/奖励路径；已知配音模拟输入不代表儿童发音准确率。
